# Panda 两轴动作执行延迟：对照实验设计

状态：2026-11-14 设计，未实施正式评估、未启动训练。用于研究执行延迟与控制稳定性，不预设 RL 优于传统控制。当前场景是仿真中的两轴关节目标到达，不能据此推断真机或完整机械臂的效果。

## 1. 已有事实与本实验要回答的问题

现有环境每个控制步为 20 ms：策略输出两轴归一化动作，乘以 0.02 rad 后作为位置命令增量；实际关节位置由 MuJoCo 的位置执行器响应。观测为 `(q, dq, goal, ctrl)` 共 8 维，其中 `ctrl` 是已应用的位置命令。现有 `panda_reach.py evaluate` 将动作先送入 FIFO，回合开始时队列填零，延迟期间观测仍是当前状态。它不模拟感知延迟、丢包或随机执行时间。

已有位置基线按 `clip((goal - ctrl)/0.02, -1, 1)` 发命令，没有考虑排队中尚未执行的增量。其旧延迟结果可帮助诊断，但不能代表具备延迟补偿的传统控制器。现有环境首次同时满足位置、速度阈值就结束，旧日志不能证明之后能持续保持。

问题依次是：① 无延迟训练的策略遇到执行延迟后，成功、超调和保持能力怎样变化？② 考虑在途动作的传统控制能恢复多少性能？③ 若之后进行延迟感知 RL 改进，在相同可用信息及动作约束下是否有增益？延迟范围目前是工程假设，不声称反映真实设备。

## 2. 延迟注入和控制器

主场景固定动作延迟 `d = 0、1、2` 个控制步，即 `0、20、40 ms`。只延迟**命令执行**；状态、目标和已应用 `ctrl` 无延迟、无噪声。每个回合从同一 home 初态重置，清空队列并以 `d` 个零动作填满。时序：在 `t=k×0.02 s` 读观测，策略给出 `a_k`；执行最早排队动作、把新动作放入队列并推进 20 ms。`d=0` 表示本步立即执行 `a_k`。例如 `d=2` 时 `a_0` 在第 3 个控制步执行，其起始时间为 40 ms。整条延迟链必须对所有方法一致；所有提交和执行动作都受相同的归一化边界、增量限幅及执行器位置限幅约束。

| 组别 | 输入与动作 | 定位 |
| --- | --- | --- |
| 位置目标基线 | 现有 8 维观测，按当前 `ctrl` 计算增量 | 复现旧基线、诊断延迟影响 |
| 延迟感知位置控制 | 8 维观测、在途命令 FIFO 和固定 `d` | 强化传统对照，避免忽略队列 |
| 原始 SAC | 现有 8 维、确定性 Actor | RL 原始基准；先核实可用 checkpoint、训练协议与设备 |
| SAC + HER + 奖励塑形 | 与原有实验一致的 8 维、确定性 Actor | 已有较好结果的 RL 候选，先研究其延迟鲁棒性 |

队列感知控制器用已应用 `ctrl` 预测所有排队增量执行后的命令位置：按先进先出依次做 `c ← clip(c + 0.02 a_queued, lower, upper)`；然后发送 `clip((goal-c)/0.02, -1, 1)`。不得一次性对队列求和后才裁剪：临近限位时其结果可能不同。它预测命令位置，不声称预测了实际关节动力学。需先验证 FIFO 索引、`d=0`、初始零队列以及靠近命令限位的行为。

对照分两层解释：现有 8 维 SAC 与现有位置基线具有相同观测；队列感知控制器比现有 SAC 多使用已发送命令历史，是额外的强对照，不能据此单独归因于算法优劣。如果将 RL 输入扩展为相同 FIFO 后重训，才构成双方都具有命令历史的主要对比。这个输入维度、模型和训练接口改动尚未完成，不能将旧 checkpoint 当成队列感知模型。后续可探索固定长度队列补零并加入有效长度；保留同等训练步数、网络预算和验证集选型规则，报告新增训练成本。

可选第二阶段在验证集调节带阻尼或考虑关节速度的 PD / 预测控制器，以更强的经典方法交叉验证；控制器能访问的观测、队列和动作上限要在表中列清楚，参数只在验证集选择。若简单队列控制已解决问题，应如实报告。任务范围扩大或动态环境更复杂时才考虑 RL 残差；残差加传统动作后的最终指令仍须受同样限幅，且与传统控制本体做消融。

## 4. 评价指标与事件定义

令 `e_k = max_i |goal_i - q_i(k)|`、`v_k = max_i |dq_i(k)|`，`Δt = 0.02 s`。合格状态要求 `e_k < 0.01 rad` **且** `v_k < 0.05 rad/s`，与现有阈值一致；两轴均需满足。各方法从第一个策略请求时刻 `t=0` 计时，排队等待计入时间，不从动作实际执行才计时。

| 指标 | 定义与用途 |
| --- | --- |
| 首次到达率及 `T_first` | 首次进入合格状态的比例；时间为 `kΔt`，对照现有首次成功口径。首次到达不能证明保持。 |
| 保持成功率、`T_confirm` | 记录从某采样点起连续 **11 个采样点**均合格，即覆盖 10 个完整控制间隔、0.20 s；`T_confirm` 是第 11 点时间，包含延迟与保持时间。评估整个固定 250 步，失败优先，任何时刻出现物理失败则该回合不计入安全保持成功。 |
| 有限时域稳定时间 | `T_confirm` 的累计成功曲线及 5 s 截尾均值 `∫₀⁵[1-F(t)]dt`；未完成或物理失败按 5 s 计入。需同时报告失败和超时数，成功样本平均时间只作附加描述，不能独立比较。 |
| 超调 | 每轴初始目标位移不为零时，`max(0, max_k sign(goal_i-q_i(0))×(q_i(k)-goal_i))`，单位 rad。分别报告各轴和两轴最大值分布；初始目标位移接近零的轴标记不适用。 |
| 误差与恢复 | 整段有效轨迹的 `Δt × Σe_k`（rad·s），以及固定末段误差的中位数/P95；记录首次到达后是否再次出界。物理失败的轨迹长度不同，积分不可直接与完整轨迹混为一谈，分层报告失败和完整轨迹。 |
| 安全与执行 | 回合物理失败、实际关节越限、数值异常和 MuJoCo warning 分别计数；同时报告发出动作与实际执行动作的饱和率、命令裁剪率。安全以模型当前限位和数值判定为准，不能代替碰撞、力矩或真机安全验证。 |
| 控制代价 | 按相同单位报告每轴实际命令增量总变差、最大 `|q-ctrl|`、控制器计算耗时中位数/P95；区分模拟时间与计算墙钟时间，说明硬件、线程及计时范围。 |

评估必须从 `t=0` 记录初始状态，每步记录发送动作、队列、实际请求和应用增量、`q/dq/goal/ctrl`、仿真时间、失败与裁剪。固定 250 步便于比较末段与再次出界；物理失败应立即停止并保留失败原因，不能为补齐时长继续运行。计算末段误差时应只在有完整末段的安全轨迹上报告，同时给出对应分母。额外可报告首次进入保持窗的时间，但必须以 `T_confirm` 作为能确认保持的时间，避免预先知道未来。

**实现门槛：** 原 `PandaTwoJointEnv.step()` 一旦首次成功会设置 `finished=True`，不能只改分析脚本就计算保持。需增加独立的评估模式或专用评估环境：首次达标只记录事件、不结束，仍立即中止真实物理失败，250 步超时；不得改变原训练终止、奖励和 HER 语义。用确定动作序列验证 0/1/2 步 FIFO 与位置命令，检查一步的时间、动作、限幅、真实失败优先、11 点保持窗及超时边界。验收前保持指标不可报告为已计算。

## 5. 预先约定的比较与统计

主要比较：按延迟分别报告两类 RL 和两类传统控制的安全保持成功率、`T_confirm` 截尾均值与超调，并给出 0→40 ms 的变化；所有模型使用同一目标配对。主要判断顺序：先比较安全保持成功率，再看在相近成功与安全水平下时间、超调及计算代价；不能只挑一个对自己有利的指标宣称全面胜出。

以目标为配对单位计算每个训练 seed 的 RL − 传统控制成功率差；同时展示每个 seed，而不是把五个 seed 对同一个目标的结果当成 480 个互相独立目标。可按训练 seed 和目标做分层/层级 bootstrap（目标在四象限内重采样，训练 seed 成组重采样），给出 95% 区间及差值；传统控制器没有训练 seed，重采样时共享同一控制器结果。只有五个训练 seed 时区间不稳定，须报告各 seed 与范围，避免夸大显著性。所有三个延迟、所有预设方法和失败案例都要展示；比较延迟感知 RL 时使用相同队列信息的传统基线。复杂目标、质量变化、观测噪声及未知/随机延迟是未来独立实验，不能据本结果推断。
