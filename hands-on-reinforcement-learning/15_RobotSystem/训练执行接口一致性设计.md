# Panda 两轴训练与执行接口一致性设计

状态：2026-11-14。已完成一段离线物理循环检查和可选插值模式；ROS 实际通信、连续动作、策略适配器及端到端一致性尚未完成。此设计不代表已有模型已经按新模式训练或可以部署。配套 [延迟实验设计](动作延迟对照实验设计.md)。

## 需要保证什么

| 项 | 训练/评估契约 | ROS 执行侧核对 |
| --- | --- | --- |
| 模型与初始状态 | 固定 Menagerie 版本和依赖；从 `home` 重置，保存模型及源码 hash | 核对同模型、物理版本、七轴和夹爪初态、reset 完成后的首个仿真时间 |
| 观测 | `(q1,q2,dq1,dq2,goal1,goal2,ctrl1,ctrl2)`，关节顺序、rad、rad/s；`ctrl` 为实际保持目标 | 按关节名映射；为接收和状态标时间，缺失/重复/NaN/陈旧状态拒绝推进决策；显式补齐 goal 和已应用 ctrl，而不是把命令终点误作已应用值 |
| 动作 | Actor 输出两轴归一化 `[-1,1]`；训练入口乘 0.02 rad，环境按每轴增量限幅和位置限位裁剪 | 适配器做一次相同缩放和限幅，其余五轴及夹爪保持；核对实际下发与接收端应用；两侧不得重复缩放 |
| 时间和推进 | 控制周期 20 ms，物理步长 2 ms；说明控制起点、采样点及 10 个物理步上的目标 | 以被接收的仿真时刻为相对零点；记录消息墙钟和仿真时间，拒绝把墙钟和仿真时钟直接相减 |
| 轨迹 | 原 `hold` 是先设置终点再推进；新增 `linear` 是每个物理步前按 `i/10` 插值 | 当前 ROS 节点接收后按物理时间线性插值；轨迹起点必须与当前保持目标连续，结束/busy/心跳与 reset 有额外约束 |
| 结束与保护 | 首次达标或实际物理失败 `terminated`，250 步超时 `truncated`；失败优先 | 不能把 ROS 命令完成、运动达到目标和 RL 任务成功混为一谈；忙碌、拒绝、超时、状态陈旧、重置单独记录，适配器按失败策略处理 |

延迟实验需另规定动作进入/退出 FIFO 的时刻、队列初始化与控制器能访问的历史。ROS 的网络/调度实际延迟和仿真中人为注入的 20/40 ms 命令延迟各自测量，不能把二者混称或重复施加而未记录。

## 当前差异和已完成的最小修复

旧训练默认调用 `PandaTwoJointEnv` 的 `hold`：在 20 ms 起始直接设置新目标，再连续推进 10 步。现有 ROS `JointTrajectory` 从当前目标向终点插值，每步前设置目标。20 ms 轨迹在前 10 次物理步开始时分别使用 0% 至 90% 的进度，第 11 步才处理末点与结束；下一条立即到达的命令可能因 `busy` 被拒。

环境新增 `control_mode='linear'`，复用相同起始保持值、每物理步先插值再推进的前 20 ms 语义，观察值中的 ctrl 是第十次步进实际使用的保持目标。`info['target_rad']` 是所请求终点，`info['held_target_rad']` 是最后应用目标，`applied_increment_rad` 是保持值实际变化。默认仍是 `hold`，原 SAC 命令和旧 checkpoint 行为不切换。直接实例化示例：

```python
env = PandaTwoJointEnv(scene, control_mode='linear')
```

此模式只是第一段物理循环对齐：当前训练入口没有提供该选项，也没有实现 ROS 连续接收/反馈的等价机制。不能以它声称完整训练接口与 ROS2 一致，更不能把旧模型称为用插值模式训练。下一阶段需同时解决训练入口配置持久化、模型加载契约和 ROS 下一命令接收机制后，才能选定统一的可训练执行协议；有任何更改都要重做原策略及控制器的同协议对照。

## 下一步分层验收

1. **单元和边界：** 对零动作、正负饱和、靠近限位、reset 后首步和物理失败，核对缩放、限幅、状态顺序、先插值后步进及终止优先级；检查错误、非有限值和版本不兼容。记录实际结果和固定输入，不用推测通过。
2. **多动作时序协议：** 在确定统一架构前，分别验证当前节点 20 ms 接收、轨迹忙碌与第 11 步释放；决定采用可中断/连续 setpoint 接口，还是明确训练与控制周期、等待及保持规则。选择应保留首点连续、顺序、超时及保护，并考虑动作在途队列和观测取样时间。每个候选都需记录 3 条以上相邻动作的接受、应用和状态时间线；不能仅把离线 `linear` 多次调用当作 ROS 已接受。
3. **ROS 集成：** 在隔离 ROS 域、固定模型和 home，实际启动接收节点与适配器，记录动作请求、接受/拒绝、应用目标、`JointState`、`/clock`、心跳和 reset。20 ms topic 无法还原每个 2 ms 应用目标，须新增物理步诊断或独立录制；分别用相对仿真时间和有序事件对齐，检查丢帧、超时与停发保护。
4. **闭环对齐：** 固定同初态和确定性动作序列，比较至少零动作、单次阶跃、变号/相邻动作、靠近限位、超时或忙碌等用例。默认同平台先逐物理步比较；如跨 Windows/WSL 或不同依赖，以预先约定容差比较并报告版本与误差曲线。端到端还需确认动作到状态一一对应及相同结束原因。容差由首个受控基线测得后在看正式实验前冻结，不先假定跨平台数值完全一致。
5. **策略和评估接入：** 将已冻结的接口版本、插值/周期、状态顺序、缩放与模型 hash 写入训练配置及 checkpoint；加载时强制比对。用固定 checkpoint 小样本对比相同输入下 Actor 输出，并分别检查 ROS 接收与实际轨迹。出现 mismatch、丢状态、心跳超时或非有限动作时安全停止/保持并记录，不把占位策略伪装成已训练模型。

只有上述相应层全部通过，才能对相应范围声明一致；代码抽取对照和 ROS 端到端属于不同证据。无需启动大规模训练来验证接口。
