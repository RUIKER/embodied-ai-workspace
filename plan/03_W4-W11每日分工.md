## 仿真项目与本人 debug 验收

项目问题是机械臂执行动作块时，观测更新频率如何影响响应时间、动作连续性和任务结果。Agent 实现仿真、策略接入、固定协议与日志，并准备可复现的 debug 样例。本人运行一条链路、解释输入输出与评估口径，完成一项定位并复核修复，最后用自己的话讲一次结果和边界。

优先练习相机预处理：Agent 在独立练习入口中可控地注入一次图像旋转错误，保留已知正确输入、相同初态和模型配置，并提供检查图像朝向的入口。本人的 1h 工作按复现异常、检查图像及处理前后、提出原因、修复并复跑的顺序进行。记录现象、假设、检查、改动与复验；训练数据和正式评估入口使用原有正确预处理。任务成功率变化不能预设，若异常不明显，转为图像差异与方向检查。练习明确标为人为注入；真实故障若出现另行记录。

现有标准 π₀.₅ 反馈对照、REACT 官方小模型测试与 ACT 单批更新均为 agent 验证。本人复现和 debug 在完成后单独记账。正式项目结论依实际 checkpoint、固定测试协议、逐回合结果及本人分工撰写；标准 π₀.₅ 和 REACT 真实权重闭环分别报告。

## 停止条件与分工

- 现有 REACT 官方 CPU 小模型测试、ACT 单批、LIBERO 示范回放和标准 π₀.₅ 单次新旧观测对照属于 agent 结果。本人实践单独记录。
- 主攻 RL 与经典控制。仿真及后训练作为冲刺，保持复现与解释入口。若控制训练或课程阻塞，优先交付控制基线、日志、失败分析和简历证据。
- agent 负责代码、环境、对照脚本及短 smoke，本人复现、理解和口述，实际用时不预填。
- 规划仅允许几十秒 smoke、已有结果聚合及脚本修改。正式训练及大规模实验先列可运行命令、预计耗时、数据与新建输出目录，由本人决定当次是否启动。
