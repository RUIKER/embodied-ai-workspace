## 任务与来源

项目暂定位置：`hands-on-reinforcement-learning/15_RobotSystem/`。使用 [MuJoCo Menagerie Panda](https://github.com/google-deepmind/mujoco_menagerie/tree/main/franka_emika_panda)，固定模型提交和依赖版本，保留 Apache-2.0 许可证。已读取其官方 README，确认现成位置执行器与 MuJoCo 最低版本要求；本机加载仍待验证。

基础环境优先沿用现有 WSL2 Ubuntu 22.04 / ROS2 Humble。先检查真实系统版本，不把旧计划中的环境文字当作已安装事实。Python 节点用 ROS 兼容的系统 Python / 受支持的环境；Humble 的系统 Python 与现有 RL Python 3.12 虚拟环境分开，不能直接混装 rclpy。无需搬动已有 RL 环境。

## 最小闭环

1. Python 仿真节点加载 Panda，独立固定步长推进；7个臂关节和夹爪映射从模型核对，不靠数组位置猜测。
2. C++ `rclcpp` 轨迹发布器发送 `trajectory_msgs/JointTrajectory`；Python `rclpy` 接收、检查关节名、点序、时间、有限值和限位，按明确的插值规则执行。
3. 发布 `sensor_msgs/JointState` 和 `/clock`；提供 `std_srvs/Trigger` reset。reset 限定为停机/空闲时使用，重置后使旧命令失效，说明时间回退与数据分段。
4. `rosbag2` 记录状态、时钟和轨迹命令；离线分析脚本读数据，生成误差表、频率统计和图。
5. 一条 launch 命令启动；有命令停发、节点退出、非法输入的诊断。限位与超时策略是软件防护，不宣称保证真机安全。

自有轨迹接收器不是 `ros2_control` 的 `joint_trajectory_controller`，topic 命令也不是 `FollowJointTrajectory` action。接口名称和简历表述遵循实际实现。

## 时间与执行语义

- 物理 dt、轨迹控制更新周期、状态发布周期分别配置并落盘；目标频率先定100Hz级，最终值按机器测得能力选定，禁止标成硬实时。
- 仿真节点掌握推进和 `/clock`，不能让自己的推进定时器依赖尚未推进的仿真时钟。消费端明确设置 `use_sim_time`；启动时等待首个时钟，避免0时间戳。
- 轨迹第一点、`header.stamp`为零/非零、`time_from_start`、插值和抢占的语义写清；只支持一种明确策略即可。关节位置rad、速度rad/s；匹配执行器ctrlrange后再发命令。
- 命令新鲜度用单调墙钟检查，便于发现仿真暂停/命令停发；ROS消息时间用于仿真对齐。分别报告两种时间，不跨不同时间域相减来计算延迟。
- 状态topic选择并记录QoS；轨迹采用可靠传输并检查兼容性。队列深度和丢弃旧命令策略须可解释。仿真暂停不等于链路延迟，两类故障分开测。

## 验收清单

| 层 | 必须拿出的证据 | 状态 |
| --- | --- | --- |
| 模型 | 来源SHA/许可证、joint-actuator表、位置控制阶跃响应、reset后初态 | 待做 |
| 构建通信 | 干净shell下colcon build；C++发布→Python接收；参数/日志/launch | 待做 |
| 轨迹 | 固定的3组限位内关节轨迹；参考值与实测按同一仿真时间插值比较 | 待做 |
| 指标 | 每关节跟踪RMSE、峰值/稳态误差，状态发布率及间隔分位数，完整配置 | 待做 |
| 保护 | 非法关节名、NaN/越界、乱序时间点、命令停发：拒绝或进入说明过的保持状态，并有日志 | 待做 |
| 数据 | rosbag2可读；命令/状态时间覆盖；离线图可从bag重建 | 待做 |
| 回放 | 仅bag回放时关闭live发布器，clock只保留一个来源；重新执行命令时只回放命令并使用live clock | 待做 |
| 复现 | 冷启动两次、重置后重复固定轨迹；比较误差；README记录差异与限制 | 待做 |
| 表达 | 90秒介绍、10分钟数据流解释、至少3类失败及定位过程 | 待做 |

预先固定测试集：3组关节轨迹、每组重置重复3次，属于短功能检查，不做大规模学习实验。记录起始关节角、关节目标、时长、seed（如有随机性）、模型SHA、依赖、控制/物理周期。

稳态误差初始验收目标可设为每关节≤0.05rad，必须在调试集确认可行后、正式评估前固定；失败如实报告，不修改评估轨迹来“过关”。运行频率和延迟不预填达标数字，先报告实测分布和机器条件。轨迹正确性、限位检查、命令停发行为和数据可复现是必过项。

录包的状态回放只证明数据链路；重置初态后重新执行命令才检验物理轨迹复现。不能把两者混写。
