# 轨迹执行与时钟

> 固定轨迹插值、输入校验和仿真时钟发布已通过冒烟。命令停发检测、抢占和 reset 服务仍待正式验收。见 [冒烟协议](../../hands-on-reinforcement-learning/15_RobotSystem/README.md#ros2-端到端冒烟)。

## 1. 一条轨迹如何变成控制输入

1. `JointTrajectory.joint_names` 决定每个点里数值的顺序。先检查关节名是否缺失、重复或未知，再检查点的维度、有限值、限位和 `time_from_start` 顺序。
2. `header.stamp` 提供轨迹参考时间，`time_from_start` 是每个点相对起点的时长。冒烟只接收零时间戳且第一点相对时间为零的轨迹，从 `home` 开始执行。正式接收器还需确定晚到命令与抢占策略。
3. 按明确的一种插值规则求 `q_ref(t)`，映射到 `ctrl`。命令校验失败时记录原因。无有效命令、命令超时及正常到达轨迹末尾时的行为分别定义。消息字段见 [JointTrajectory](https://raw.githubusercontent.com/ros2/common_interfaces/humble/trajectory_msgs/msg/JointTrajectory.msg) 和 [JointTrajectoryPoint](https://raw.githubusercontent.com/ros2/common_interfaces/humble/trajectory_msgs/msg/JointTrajectoryPoint.msg)。

## 2. 哪个钟负责什么

| 时间或周期 | 用途 |
| --- | --- |
| 物理步长 `dt` | 每次 `mj_step` 推进的仿真时长。 |
| 控制更新周期 | 重新计算轨迹目标的间隔。 |
| 状态发布周期 | 采样并发布 `JointState` 的间隔，实际间隔另测。 |
| 仿真时间 `/clock` | 给轨迹、状态和离线评估提供共同时间轴。仿真端负责推进，消费端启用 `use_sim_time` 后等待首个时钟。 |
| 单调时钟 | 计算距上次收到有效命令的实际经过时间。超时检查应在仿真暂停时仍有调度机会。 |

仿真推进的定时器应独立于自己发布的 `/clock`。空闲时 reset 会让仿真时间回退，同时清理旧轨迹和插值状态，按新一段记录处理。用仿真时间比较轨迹与状态，用单调时钟报告本地命令间隔，两个时间域分别记录。依据见 [ROS2 Clock and Time](https://design.ros2.org/articles/clock_and_time.html)。

## 3. 自测

- **故障预测**。轨迹收到后暂停仿真，再让发布器停止发命令。若 watchdog 由仍在运行的单调时钟调度，它可以记录超时并使旧命令失效。恢复推进前检查保持状态是否生效。
- **面试一句话**。项目设计用自有 topic 接收器做限位、插值和超时处理，`FollowJointTrajectory` action 与 `ros2_control` 属于单独的接口与框架。以 [工程验收](../11_工程主线验收.md) 标注实现状态。
